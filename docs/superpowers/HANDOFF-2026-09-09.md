### The single most important finding

**There is no detectable mean signal to add.** On 10,131 fitted player-weeks,
not one environment or matchup coefficient is distinguishable from zero
(max |t| = 1.91). Log-residual sd is 0.57–0.84 — the noise floor swamps
anything left after Sleeper's own projection. The calibration therefore keeps
a coefficient only when |t| ≥ 2, which zeroes alpha, beta and gamma entirely.
**Sigma (0.60–0.72, delta 0.294) and correlations (game .115 / team .21 /
unit .265) survive** as measured quantities. So the shipped model is
off-state mean + fitted spread + fitted correlation. Recorded in the spec.

Consequence for Task 17: **gate 1 ("beat raw Sleeper on RMSE") will TIE, not
win**, by construction. Report that verdict as-is. Do NOT reword the gate after
seeing the data. Leg A's value is the distribution, not the mean.

## How to run the SDD loop (what worked)

- Skill dir: `~/.claude/plugins/cache/claude-plugins-official/superpowers/6.3.0/skills/subagent-driven-development/`
- Per task: record BASE sha → dispatch implementer (haiku for transcription of
  complete code, sonnet for integration/judgement) with brief path + GLOBAL.md
  path + report path → `review-package <plan> BASE HEAD` → dispatch reviewer
  (sonnet) → fix rounds via SendMessage to the same implementer → scoped
  re-review (haiku) → ledger `Task N: complete`.
- **Never dispatch two implementers at once** (same-branch commit race).
  Reviewer + implementer concurrently is fine.
- **Pre-verify the plan's expected values yourself before dispatch**, so a
  failing test means the code is wrong, not the expectation. This caught
  several plan defects early.
- **Ask implementers for judgement, not just compliance** ("do these numbers
  look like plausible football?"). Task 13's plausibility check found the
  WSH bug and the 34%-zero-projection hole; no unit test would have.
- **Tell implementers to state disagreements, not diverge silently.** Nine
  did, and every one found a real defect in the plan.
- Every task so far needed ≥1 fix round, almost always for a plan defect.
  Recurring classes: sign inversions, `Number("")` coercion, tests that
  cannot fail, guards that clamp instead of validate, hand-copied sets that
  already exist in the codebase, tuned numbers hardcoded outside config.
